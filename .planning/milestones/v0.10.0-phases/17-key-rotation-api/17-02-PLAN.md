  <action>
Create `tests/test_key_rotation_api.py` with tests covering all SEC-04 criteria and CONTEXT.md decisions.

**Setup helper:** Reuse the `_make_signed_cache` pattern from `tests/test_key_rotation.py`. Also create a `_generate_key_file(path)` helper that writes 32 random bytes to a file and returns the path.

**Test class: `TestUnifiedCacheRotateKey`**

1. **test_basic_rotation** — Create signed cache, put 3 entries, generate new key file, call `rotate_key(new_key_file)`. Assert RotationResult: total=3, re_signed=3, failed=0, skipped=0. Then create a new cache instance with the new key (delete old key, use new one) and verify all 3 entries are readable.

2. **test_rotation_result_counts** — Put entries, call rotate_key, verify RotationResult fields are accurate.

3. **test_rotation_idempotent** (per D-09) — Call rotate_key twice with same key file. Both calls should succeed. Second call re-signs already-v3 entries to v3 again (same result).

4. **test_v2_to_v3_migration** (per D-04) — Create cache with `use_hkdf_derivation=False` (entries signed as v2). Then rotate key with `use_hkdf_derivation=True`. Verify entries are now v3 signatures. (Note: this requires creating the cache with hkdf disabled, then enabling it during rotation. The rotate_key method creates a new signer that respects the config's `use_hkdf_derivation`.)

5. **test_namespace_re_signed** (per D-12) — After rotation, verify namespace signature changed (query metadata backend's get_namespace, check signature is not None and different from pre-rotation).

6. **test_entries_verify_after_rotation** — After rotation, each entry's signature should verify with the new signer. Create fresh cache instance with new key, get each entry — should succeed.

7. **test_rotation_without_signing_raises** — Create cache without signing. Call rotate_key. Assert `CacheSecurityError` raised.

8. **test_invalid_key_file_raises** — Call rotate_key with nonexistent path. Assert `CacheSecurityError`. Also test with a file that's not 32 bytes.

9. **test_old_key_entries_handled_after_rotation** (SEC-04 criterion 3) — After rotation, delete old key file, restart cache with new key. Old entries should still be accessible (version routing handles v2→master_key, v3→derived_key).

**Test class: `TestBlobStoreRotateKey`**

10. **test_blob_store_basic_rotation** — Create BlobStore with `enable_signing=True`, put 3 blobs, generate new key, call `rotate_key(new_key_file)`. Verify counts and that blobs are readable after rotation.

11. **test_blob_store_rotation_without_signing_raises** — BlobStore without signing, rotate_key raises `CacheSecurityError`.

12. **test_blob_store_entries_verify_after_rotation** — After rotation, get() succeeds for all blobs (signature verification passes with new signer).

**Important patterns:**
- Use `tmp_path` fixture for all test directories.
- Use `secrets.token_bytes(32)` for generating new key files.
- Import `CacheSecurityError` from `cacheness.error_handling`.
- Import `RotationResult` from `cacheness.interfaces`.
- Follow existing test patterns in `test_key_rotation.py`.
- Use `pytest.raises(CacheSecurityError)` for error cases.
