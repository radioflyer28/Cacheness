<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Independent process → shared SQL projection | Cross-process correctness must come from a database transaction, not an object lock. |
| Projection row → custom metadata link | Link ownership must change with the exact projection token in one transaction. |
| Cached wrapper → wrapped SQL backend | The wrapper must preserve capabilities, transactions, and cache invalidation without leaking session ownership. |
| PostgreSQL decoded row → signature verifier | Read-back nesting must reproduce the fields that were signed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03-16-01 | Tampering | SQLite projection CAS | high | mitigate | Acquire BEGIN IMMEDIATE before comparison and keep row/link mutation plus classification in that transaction. |
| T-03-16-02 | Tampering | PostgreSQL expected absence | high | mitigate | Acquire a stable bound per-key advisory transaction lock before absence/presence read and commit exact result atomically. |
| T-03-16-03 | Tampering | Delayed custom link | high | mitigate | Recheck exact current projection inside the object/link insertion transaction and roll back all stale objects/links. |
| T-03-16-04 | Spoofing | Cached backend capability | high | mitigate | Use explicit custom-metadata protocol methods and backend-owned context managers; reject unsupported paths explicitly. |
| T-03-16-05 | Tampering | PostgreSQL signing input | high | mitigate | Restore key parameters at the canonical nested path and verify end-to-end before any invalid-signature retirement policy. |
| T-03-16-06 | Denial of Service | Database contention | medium | mitigate | Keep locks transaction-scoped, bind keys, honor existing busy/deadline policy, and never span payload work. |
</threat_model>
