Purpose: Give stopped-worker rebuild orchestration one backend-neutral way to retry an exact destination mutation and reconstruct the same projection-free canonical receipt after response loss while preserving ADR 0001's single-authority model and D-11's post-acceptance derived boundary.
Output: One immutable operation replay contract, authority parity across memory/SQLite/deterministic PostgreSQL, a narrow BlobStore/lifecycle canonical-maintenance operation-ID seam, and focused projection-equipped contract tests.
</objective>

<interfaces>
`BlobStore.put_entry()` currently turns the canonical `_receipt_for_result()` into `BlobReceipt(operation_id, key, generation, locator, expectation, catalog_revision, projections)` and then adds derived outcomes through `_run_post_commit_projections()`. `AuthorityLifecycleEngine.put()` currently generates a fresh operation ID immediately before `LifecycleAuthority.prepare_mutation(MutationSpec)`; memory, SQLite, and PostgreSQL authorities already persist exact operation-keyed mutation records and make prepare/promotion replay-safe for the same exact spec. This plan adds one bounded read primitive plus a narrow maintenance wrapper around the same engine, not a second write lifecycle or authority.
</interfaces>

<planner_assumptions>
- MIGR-05 and MIGR-06 need an exact retry seam before rebuild evidence can persist and resume destination writes; incidental destination keys never prove progress.
- The response-loss repair remains wholly inside the existing lifecycle contract: the single canonical destination authority records the exact `MutationSpec` before immutable payload publication and classifies retry per D-19 and D-20.
- No coordinator, queue, lease, lock, second authority, listing scan, or entry-adoption path is permitted by ADR 0001.
- D-11 requires rebuild staging to commit canonical destination entries without automatic projection effects. The maintenance seam is an internal BlobStore wrapper over `_put_with_result_admitted`; ordinary `put_entry()` keeps its current projection behavior, while `OfflineMigrationService.rebuild_projection()` remains the only explicit post-acceptance derived path.
- The obstore spike validates the same prepared-intent -> immutable deterministic locator -> digest-and-size observation -> authority-promotion sequence, but this plan implements the missing replay seam against the existing `BlobStore` participant contract. It introduces no obstore dependency or publication-policy choice.
</planner_assumptions>
