# Phase 07.1 Plan 07: Read-Only Transport Comparison Summary

**Committed generations can now be checked against one exact opaque transport observation without a payload download, while every ordinary read still verifies SHA-256 before deserialization.**

## Accomplishments

- Added a backend-neutral optional `PayloadTransportObservationProvider` and implemented it in the obstore generation participant without coupling `BlobStore` to the concrete adapter.
- Added public immutable comparison results for `MATCH`, `MISMATCH`, `UNAVAILABLE`, and exact-object `ABSENT`; a result always carries the committed key, generation, and locator and always reports canonical payload verification as false.
- Authenticated signed evidence against the selected committed manifest before the one head observation, retaining typed backend causes and refusing malformed or transplanted evidence before participant I/O.
- Proved the comparison is mutation-free and that a prior match cannot bypass the ordinary read path's snapshot download and SHA-256-plus-size verification.

## Decisions Made

- A match is an opaque transport corroboration result, never a payload digest, lifecycle decision, repair signal, promotion, deletion authority, or handler-deserialization authorization.
- Only an exact typed missing-object error becomes `ABSENT`; permissions, network, configuration, and malformed adapter responses remain typed failures with original causes where applicable.
- The optional observation protocol is structural so selected custom/injected payload providers remain valid without it and safely return `UNAVAILABLE`.
