<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Opaque backend ID to filesystem path | Caller-controlled identifiers determine sharded filesystem locations. |
| Persisted/direct locator to OS operation | A path string may be absolute, cross-platform-shaped, outside-root, or retargeted. |
| Resolved root to managed descendants | The root symlink is trusted configuration; descendant symlinks/reparse points are not. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering / Information Disclosure | blob ID and locator parsing | high | mitigate | Host-independent grammar and containment validation reject traversal, absolute, drive, UNC, rooted, mixed, and outside-root paths before any operation. |
| T-01-02 | Tampering | FilesystemBlobBackend writes/deletes | high | mitigate | Operation-scoped guarded parent handles, unique contained temporary files, no-follow access, and typed failures prevent outside writes/deletes. |
| T-01-03 | Elevation of Privilege / TOCTOU | managed symlink/reparse components | high | mitigate | Anchor the canonical root; use descriptor-relative no-follow traversal on capable Unix; use locked repeated reparse/containment checks on Windows/fallback; exercise all five resolved race tiers and state the trusted-host residual explicitly. |
| T-01-04 | Denial of Service | hostile identifier/resource abuse | medium | mitigate | Bound identifier length and grammar before path allocation or directory creation. |
</threat_model>
