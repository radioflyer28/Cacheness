  <action>
    1. Change line 236 from `self._lock = threading.Lock()` to `self._lock = threading.RLock()` — add a brief comment: `# RLock: allows re-entrant acquisition from composed operations`

    2. Audit ALL public methods in SqliteBackend. The following methods currently DO acquire `self._lock`:
       - `put_entry()` (line 339)
       - `get_entry()` (line 472)
       - `remove_entry()` (line 685)
       - `update_access_time()` (line 800)
       - `update_entry_metadata()` (line 823)
       - `clear_all()` (line 1042)
       - `cleanup_expired()` (line 1055)
       - `cleanup_by_size()` (lines 1068 and 1097)
       - `create_namespace()` (line 1084)
       - `update_stats()` (line 1141)

    3. The following public methods currently DO NOT acquire `self._lock` — add `with self._lock:` wrapping:
       - `iter_entry_summaries()` (line 865): wrap the entire method body in `with self._lock:` — this method calls `.fetchall()` so all data is materialized before returning, no generator/yield issue
       - `list_entries()` (line 923): wrap the entire method body in `with self._lock:`
       - `get_stats()` (line 996): wrap the entire method body in `with self._lock:`
       - `list_namespaces()` (line 499): wrap the entire method body in `with self._lock:`

    4. Do NOT add locking to `close()` or `__del__()` — these are cleanup methods that should not block on locks.

    Pattern to follow for each fix — change:
    ```python
    def method_name(self, ...) -> ...:
        """Docstring."""
        with self.SessionLocal() as session:
            ...
    ```
    to:
    ```python
    def method_name(self, ...) -> ...:
        """Docstring."""
        with self._lock, self.SessionLocal() as session:
            ...
    ```
  </action>
