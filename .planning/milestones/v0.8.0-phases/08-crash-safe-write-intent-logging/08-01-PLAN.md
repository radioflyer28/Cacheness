<objective>
Implement a crash-safe write intent journal that prevents orphaned blobs from accumulating after process crashes.

Purpose: The current `_PutCleanup` handles in-process failures (exceptions) but NOT crash recovery. If the process dies between blob write and metadata commit, the blob file persists on disk with no metadata entry pointing to it — a silent storage leak.

Output: New `WriteIntentJournal` class, integration into `put()` and `_storage_mode_put()`, cleanup-on-init, and comprehensive tests.
</objective>

  <action>
    1. Create `src/cacheness/write_intent.py` with class `WriteIntentJournal`:
       - `__init__(self, cache_dir: Path, stale_threshold_seconds: float = 300.0)`:
         Creates `{cache_dir}/.intents/` directory on first use (lazy mkdir).
       - `record_intent(self, cache_key: str, blob_path: str) -> Path`:
         Writes a small JSON file `{cache_dir}/.intents/{safe_filename}.intent` containing
         `{"cache_key": cache_key, "blob_path": blob_path, "created_at": time.time()}`.
         Use a safe filename derived from cache_key (e.g., xxhash hex digest).
         Returns the intent file path.
       - `clear_intent(self, cache_key: str)`:
         Removes the intent file for the given cache_key. No-op if file doesn't exist.
       - `cleanup_stale_intents(self) -> int`:
         Scans `{cache_dir}/.intents/` for `.intent` files older than `stale_threshold_seconds`.
         For each stale intent: (a) delete the orphaned blob at `blob_path` if it exists,
         (b) delete the intent file. Returns the count of cleaned intents.
         Log each cleanup at INFO level.

    2. Add to `CacheStorageConfig` in config.py:
       - `stale_intent_threshold_seconds: float = 300.0` — configurable threshold

    3. Integrate into `core.py` `__init__()`:
       - After `self._init_blob_store()`, create `self._write_journal = WriteIntentJournal(self.cache_dir, self.config.storage.stale_intent_threshold_seconds)`
       - In the `cleanup_on_init` block (after `self._cleanup_expired()`), add `self._cleanup_stale_intents()`
       - Add method `_cleanup_stale_intents(self)`:
         `cleaned = self._write_journal.cleanup_stale_intents()`
         `if cleaned > 0: logger.info(f"Cleaned up {cleaned} stale write intents")`

    4. Integrate into `core.py` `put()` method:
       - After the `_PutCleanup` is created but BEFORE `_write_blob()`, record intent:
         Only for non-inline writes (when `direct is None`), after `_write_blob()` returns
         and we know the actual blob path, call:
         `self._write_journal.record_intent(cache_key, result.actual_path)`
       - After `self.metadata_backend.put_entry(cache_key, entry_data)` succeeds,
         call `self._write_journal.clear_intent(cache_key)`
       - In the except blocks (rollback path), also call `self._write_journal.clear_intent(cache_key)` — the _PutCleanup.rollback() handles blob deletion, intent just needs clearing.

    5. Integrate into `_storage_mode_mixin.py` `_storage_mode_put()`:
       - Same pattern: record intent after `_write_blob()`, clear after `put_entry()` and in rollback.

    6. Update `_PutCleanup` to optionally clear intent on rollback:
       - Add `intent_journal` and `intent_cache_key` slots
       - In `rollback()`, also call `self.intent_journal.clear_intent(self.intent_cache_key)` if set

    Note: Direct inline writes (no disk blob) do NOT need intent tracking — there's no orphaned blob risk.
