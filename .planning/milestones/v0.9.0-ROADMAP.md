# Milestone v0.9.0: Completeness & Hardening

**Status:** ✅ SHIPPED 2026-04-03
**Phases:** 11-14
**Total Plans:** 4

## Overview

Close remaining gaps identified in CONCERNS.md — complete the batch API surface, fix contradictory documentation, and harden security on all platforms.

## Phases

### Phase 11: put_batch() API

**Goal:** Implement the missing `put_batch()` batch operation on UnifiedCache, completing the batch operations surface alongside existing `get_batch()`, `delete_batch()`, and `touch_batch()`.
**Requirements:** MGMT-01
**Plans:** 1 plan

- [x] 11-01: Implement put_batch() with thread-safe locking and 8 tests

**Success Criteria:**
- `put_batch()` method exists on UnifiedCache and accepts a list of (key_kwargs, data) tuples
- Backend-level transaction support for SQLite
- Tests cover JSON and SQLite backends, multiple data types, partial failure handling

### Phase 12: Threading Model Documentation

**Goal:** Fix contradictory concurrency documentation and accurately document the post-v0.8.0 threading model.
**Requirements:** DOC-01
**Plans:** 1 plan

- [x] 12-01: Fix API_REFERENCE.md and TROUBLESHOOTING.md thread safety sections

**Success Criteria:**
- API_REFERENCE.md Thread Safety section documents actual RLock behavior
- TROUBLESHOOTING.md is consistent with API_REFERENCE.md

### Phase 13: Deserialization Security

**Goal:** Harden pickle/dill deserialization paths with defense-in-depth documentation and verification that existing protections cover blob tampering.
**Requirements:** SEC-01
**Plans:** 1 plan

- [x] 13-01: Document 3-layer defense model, add code comments at deserialization sites

**Success Criteria:**
- SECURITY.md documents the layered defense model
- Code comments at all deserialization sites reference the security model
- Test verifies blob tampering detected when verify_hashes=True (default)

### Phase 14: Windows Key File Permissions

**Goal:** Replace the no-op `chmod(0o600)` on Windows with `icacls`-based ACL restriction.
**Requirements:** SEC-02
**Plans:** 1 plan

- [x] 14-01: Cross-platform _set_key_file_permissions() with icacls on Windows

**Success Criteria:**
- Windows: `icacls` restricts key file to current user
- Graceful fallback on failure
- 2 new tests cover the permission code path
- SECURITY.md documents Windows key file behavior

## Milestone Summary

### Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| No backend-level batch transactions | put_batch delegates to self.put() per item — simpler, full pipeline per entry | ✓ Good — correctness over performance |
| Document existing defenses vs new code | Deserialization already protected by 3-layer model — documenting sufficed | ✓ Good — no unnecessary code changes |
| icacls over win32security | icacls is available on all Windows, no pywin32 dependency needed | ✓ Good — zero new dependencies |
