## Trust Boundaries

| Boundary | Description |
|---|---|
| qualified local artifacts -> GitHub draft | Only canonical same-SHA sanitized qualifying evidence may be uploaded. |
| release operator approval -> irreversible publication | The exact report digest must bind approval to one tag/SHA/asset set. |
| GitHub release API -> final qualification | Remote state, immutability, asset states, and digests are untrusted until independently revalidated. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-08-12-01 | Spoofing | release tag/target | high | mitigate | Resolve the intended tag to the exact candidate SHA before draft creation, before publication, and after publication. |
| T-08-12-02 | Tampering | release asset inventory/digests | high | mitigate | Require an exact allow-list, uploaded state, local/API SHA-256 equality, and content revalidation at both boundaries. |
| T-08-12-03 | Repudiation | publication approval | high | mitigate | Bind the operator's exact resume signal to tag, SHA, and prepublication report digest. |
| T-08-12-04 | Elevation of Privilege | release mutation | high | mitigate | Preflight authenticated least privilege and mutate only the exact intended draft after blocking-human approval. |
| T-08-12-05 | Information Disclosure | release assets | high | mitigate | Recursive secret scan and strict sanitized asset allow-list reject raw logs, diagnostics, credentials, and payloads. |
| T-08-12-06 | Denial of Service | immutable publication failure | medium | mitigate | Revalidate immediately before the one-way transition and report postpublication mismatches without destructive retry. |
