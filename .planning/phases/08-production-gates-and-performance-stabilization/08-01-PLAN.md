Each envelope binds a lowercase 40-character Git revision, a relevant-source SHA-256 digest, generation time, evidence class, terminal status, and class-specific sanitized payload. Only the final release verifier may combine envelopes; class producers cannot promote another class.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| child verifier -> evidence writer | Untrusted subprocess output must not manufacture a deterministic pass. |
| repository state -> evidence identity | Dirty or changed qualification sources must invalidate exact-commit evidence. |
| evidence file -> later release verifier | JSON is untrusted and must be bounded, canonical, and exact-shape. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-08-01-01 | Spoofing | deterministic evidence status | high | mitigate | Require a fixed successful child command, exact revision, clean relevant sources, and validated output before PASS. |
| T-08-01-02 | Tampering | evidence JSON | high | mitigate | Reject duplicate/unknown keys, bound input, canonicalize output, and atomically replace the destination. |
| T-08-01-03 | Repudiation | claim classification | medium | mitigate | Persist separate ADR claim categories and explicit nonclaims in every envelope. |
| T-08-01-04 | Information Disclosure | evidence payload | high | mitigate | Permit only sanitized allow-listed fields and reject unsafe text patterns before writing. |
| T-08-01-05 | Denial of Service | child execution/parser | medium | mitigate | Apply fixed timeouts and byte/item limits; preserve typed failure rather than retrying without bound. |
</threat_model>
