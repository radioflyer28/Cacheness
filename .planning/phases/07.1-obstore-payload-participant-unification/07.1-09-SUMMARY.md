## Decisions Made

- Built-in role names continue to describe topology (`memory`, `filesystem`, `s3`), not a legacy implementation type.

- Cache policy has no direct obstore import or transport coordinator; exact deletion remains a `BlobStore.delete` operation.

### Auto-fixed Issues

**1. [Rule 1 - Bug] Kept filesystem private staging outside the authority root**

- **Found during:** Task 1
- **Issue:** Creating the default handler-stage directory inside the filesystem payload root made SQLite correctly classify the uninitialized store as pre-existing evidence.
- **Fix:** Default filesystem staging now uses a participant-owned temporary root; the LocalStore root remains empty until the lifecycle authority initializes it.
- **Files modified:** `src/cacheness/storage/obstore_generation_io.py`
- **Verification:** Topology tracer and complete Plan 09 suite pass.
- **Commit:** `88c6014`

**2. [Rule 1 - Bug] Removed duplicate close of self-materializing payload providers**

- **Found during:** Task 2
- **Issue:** BlobStore closed a shared `ObstoreGenerationIO` once as handler I/O and once through the topology ledger, and could close a caller-owned injected provider.
- **Fix:** BlobStore leaves a materialized object identical to its selected payload participant to the topology ledger, preserving exactly-once store ownership and caller ownership.
- **Files modified:** `src/cacheness/storage/blob_store.py`
- **Verification:** Ownership and cache-boundary suites pass.
- **Commit:** `1c86f6a`
