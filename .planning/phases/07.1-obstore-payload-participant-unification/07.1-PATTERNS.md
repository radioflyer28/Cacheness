# Phase 07.1: Obstore Payload Participant Unification - Pattern Map

**Mapped:** 2026-09-12  
**Files analyzed:** 25 implementation, packaging, and test targets from the
research file map  
**Analogs found:** 25 / 25 (new adapter/evidence modules use partial analogs;
no existing file has the complete obstore responsibility)

This map is for the planner. It preserves ADR 0001's boundary: the payload
participant supplies byte/object primitives, while `BlobStore` and
`AuthorityLifecycleEngine` retain intent, visibility, recovery, and cleanup
authority. Do not copy the old backend's wide CRUD or multipart lifecycle into
the new adapter.

## Pattern Assignments

### `src/cacheness/storage/obstore_generation_io.py`

**Analogs:** `src/cacheness/storage/guarded_handler_io.py`, lines 148-225 and
411-442; `src/cacheness/storage/backends/s3_backend.py`, lines 350-369,
657-784, and 786-818; `src/cacheness/storage/backends/blob_backends.py`,
lines 359-424.

Use `GuardedHandlerIO.stage()` unchanged as the handler boundary: it invokes
`handler.put` in a private directory, validates the returned mapping, retains
the descriptor identity, and enforces suffixes (`guarded_handler_io.py:148-170,
217-225`). The new adapter should delegate staging to it, then pass the
retained open stream to obstore. It must never pass a handler path, obstore
locator, or remote object to a handler.

Copy the old S3 adapter's operation shape, but replace boto3 mechanics with
obstore primitives: preflight/head, bounded stream-to-private-snapshot, exact
delete followed by exact absence proof (`s3_backend.py:657-818`). Normalize
only typed not-found/collision exceptions. Do not copy `_publish_multipart`,
multipart receipts, or list-driven recovery.

The existing memory adapter is useful only as a negative comparison: it reads
the entire source into `_storage` (`blob_backends.py:382-408`). The obstore
MemoryStore path must share the same adapter contract, with no separate
dictionary authority and no `memory://` locator special case.

### `src/cacheness/storage/transport_evidence.py`

**Analogs:** `src/cacheness/storage/manifest.py`, lines 120-170 and 289-345;
`src/cacheness/storage/reconciliation.py`, lines 46-110.

Follow immutable dataclass validation and explicit version dimensions from
`StoreVersionDimensions` (`manifest.py:120-170`). Follow HMAC signing and
constant-time verification from `sign_current_manifest`/
`verify_current_manifest` (`manifest.py:329-345`), using a domain-separated,
bounded transport-evidence encoding. Follow redacted, stable status values
from `ReconciliationFinding` (`reconciliation.py:52-110`).

Evidence is opaque ETag/size/version transport observation, generation-bound
and signed by the lifecycle authority. It is not a digest, not a visibility
decision, and not a replacement for SHA-256 before deserialization. Reject
duplicate/unknown fields and oversized values; preserve explicit unsupported
version errors rather than guessing.

### `src/cacheness/storage/composition.py`

**Analog:** current `RoleRegistry` and `PayloadGenerationIOProvider`, lines
238-249, 503-515, 518-541, 691-702, and 885-929.

Retain the narrow protocol:

```python
class PayloadGenerationIOProvider(Protocol):
    def materialize_handler_io(self) -> object:
        ...
```

The registry constructs participants and validates their role; it does not
sequence lifecycle operations. Replace built-in payload registrations at the
composition point (`RoleRegistry._register_builtin_participants`, lines
525-541) and preserve injected-instance identity/ownership in `_resolve_ref`
(`885-903`). The S3 constructor remains lazy (`691-702`) so missing optional
test tooling does not alter base import behavior. D-16 means no
`expected_bucket_owner`, custom signer, boto3 fallback, or second participant
may be introduced.

### `src/cacheness/storage/lifecycle.py`

**Analog:** `AuthorityLifecycleEngine.put`, lines 392-550, and `open_entry`,
lines 778-844.

Keep the sequence visible in the existing code: private handler stage; digest
and manifest; `prepare_mutation`; participant publication; independent exact
snapshot/hash; one `record_verification`; `promote_mutation`; then cleanup
debt settlement (`lifecycle.py:401-522`). Add transport observation to the
existing verification proof, not a new lifecycle state or second authority
write. Reads must retain the bounded retry on authority expectation changes,
private snapshot, SHA-256/size check, then handler deserialization
(`lifecycle.py:783-833`).

### `src/cacheness/storage/lifecycle_authority.py`

**Analog:** `EntrySnapshot`, `VerificationProof`, and `MutationReplay`, lines
57-77 and 125-247.

Extend the immutable proof/snapshot model with bounded optional evidence while
preserving corroboration checks: entry generation/manifest digest must match,
proof manifest must match prepared manifest, and replay remains a read model,
not another state machine. Use the current `__post_init__` fail-closed style
for type, byte-size, and canonical encoding validation.

### Authority backends

**Files:** `memory_lifecycle_authority.py`, `sqlite_lifecycle_authority.py`,
`backends/postgresql_lifecycle_authority.py`.

The in-memory analog is the locked transition in
`memory_lifecycle_authority.py:216-230` followed by promotion at `245-299`:
validate exact prepared identity, store proof once, and copy it into the
promoted replay result. Do not add a lock or lifecycle state.

SQLite must use its existing short transaction wrapper (`sqlite_lifecycle_authority.py:1136-1210`),
the conditional `record_verification` update (`1303-1333`), and promotion's
single transaction (`1339-1417`). Persist evidence in the same verification
mutation and copy/read it through promotion/replay. Keep SQLite's explicit
schema/user-version validation; unsupported layouts fail and are handled by
offline migration tooling.

PostgreSQL follows `_transaction` (`postgresql_lifecycle_authority.py:334-363`)
and the conditional `record_verification` update (`1458-1483`). Use the
authority transaction as the only durable evidence write. PostgreSQL's
transaction does not include the obstore payload effect; reconciliation still
applies as ADR 0001 requires.

### `src/cacheness/storage/manifest.py`

**Analog:** `StoreVersionDimensions` and `BlobManifest`, lines 120-210, plus
`from_mapping`/`canonical_bytes`, lines 289-326.

Keep transport evidence outside canonical manifest fields unless the plan
explicitly changes the manifest contract. Preserve explicit independent schema
dimensions, SHA-256 as `PAYLOAD_DIGEST_ALGORITHM`, exact-field decoding, and
offline migration-required behavior. Use `sign_current_manifest` only for the
canonical manifest; evidence gets its own bound/authenticated representation.

### `src/cacheness/storage/guarded_handler_io.py`

**Analog:** itself, lines 95-225 and 411-442.

Retain private `TemporaryDirectory` staging, `0o700` stage roots, retained
descriptor/inode validation, regular-file checks, safe suffix grammar and
96-byte bound, and `0o600` private snapshots. Remove only managed transport
ownership (`ManagedFileOps` publication/copy/delete) once the adapter has
replaced it. Do not weaken checks because obstore accepts broader relative
names.

### `src/cacheness/storage/migration.py`

**Analog:** `migration.py:3357-3469` and
`tests/test_migration_remote_contract.py:217+`.

Preserve stopped-worker authority evidence, authenticated source snapshot
verification, exact candidate locator binding, and resumable batch progress.
Replace `write_blob`, S3-only introspection, and `memory://` branching with a
backend-neutral participant method. Same-format copies should stream the
verified source snapshot; transformed formats still call the registered
handler and route its guarded result through the participant. Never infer
activation from a listing or candidate presence.

### `src/cacheness/storage/reconciliation.py`

**Analog:** `_AuthorityReconciler._classify` and `_apply`, lines 430-625.

Keep bounded row/byte/time budgets and redacted finding construction. Reconcile
only authority-owned mutations and cleanup debt; obstore listing is bounded
maintenance evidence at most, never catalog completeness or adoption authority.
Remove multipart-upload residue categories required by D-02 without adding a
new journal, lease, or lifecycle coordinator.

### `src/cacheness/storage/blob_store.py` and `read_contract.py`

**Analogs:** `blob_store.py:773-815` and `lifecycle.py:778-848`; `read_contract.py:30-117`.

Keep `_materialize_authority_store`'s five-method structural check and lazy
participant materialization. Add the developer transport comparison as a
read-only query that resolves the authoritative generation, performs exact
head, and reports match/mismatch/unavailable/absent without repair or
authority mutation. Preserve `BlobEntry` context ownership and release
semantics; public reads still verify SHA-256 before calling `handler.get`.

### Public barrels and obsolete backend files

Use current deliberate barrel imports (`storage/__init__.py:143-157` and
`backends/__init__.py:8-63`) as the export pattern. After all consumers move,
remove `BlobBackend`, `InMemoryHandlerIO`, boto3 runtime imports/

run repository-wide symbol/import search; migration and tests are known

### Packaging

**Files:** `pyproject.toml`, `uv.lock`.

unsupported feature, not a reason to retain boto3 in production.

## Shared Patterns

### Single authority and transaction boundary

**Sources:** `docs/adr/0001-topology-specific-storage-guarantees.md:30-44,83-100`,
`src/cacheness/storage/lifecycle.py:484-522`.

Authority intent precedes external payload effects; promotion is visibility;
immutable payloads plus exact verification/reconciliation provide crash
consistency, not cross-resource ACID. Do not add locks, queues, leases,
sidecars, or timing-based recovery to make the obstore participant a second
authority.

### Narrow typed failure handling

**Sources:** `src/cacheness/storage/read_contract.py:132-157`,
`src/cacheness/storage/backends/s3_backend.py:669-709`, and
`src/cacheness/storage/reconciliation.py:471-486`.

Translate only known collision/absence errors. Preserve causes with `raise ...
from error`; never turn arbitrary remote failure into a miss or absence. Use
domain errors for backend, lifecycle conflict, integrity, and migration cases.

### Handler security boundary

**Source:** `src/cacheness/storage/guarded_handler_io.py:148-225,411-442`.

Private stage/snapshot directories, retained descriptor identity, regular-file
and suffix validation, no-follow/containment checks, and cleanup remain
Cacheness-owned. Obstore is downstream byte transport only.

### Immutable generations and exact cleanup

**Sources:** `src/cacheness/storage/lifecycle.py:162-167`,
`src/cacheness/storage/reconciliation.py:585-613`, and
`tests/contracts/test_payload_generation_io.py:119-135`.

Never reuse a locator. Delete exactly the authority-attributed generation and
prove absence with an exact head/read check. Failed cleanup remains durable
debt and is retried by the authority-owned reconciler.
