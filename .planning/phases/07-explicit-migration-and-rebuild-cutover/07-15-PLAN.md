Plan 07-14 adds `BlobStore._put_entry_canonical_for_maintenance(..., operation_id=...)` and exact projection-free canonical lifecycle replay by wrapping the same `_put_with_result_admitted` engine as ordinary writes. `MaintenanceRunEvidence` currently has rebuild states but no persisted per-write intent or receipt collection. `OfflineMigrationService.stage_rebuild()` retains receipts only in a local list, currently calls projection-running `put_entry()`, `verify_rebuild()` passes an empty receipt tuple on failure, and `resume()` has no rebuild-state branches.

<planner_assumptions>
- MIGR-05 requires authenticated durable attribution for each destination write and replay from every declared rebuild state; incidental destination keys never prove progress.
- MIGR-06 keeps rebuild separate from physical migration: reads use authenticated source handlers, writes use destination BlobStore lifecycle, and evidence never becomes destination authority.
- Destination cleanup is an external retryable effect. It preserves exact conflicting/current entries and the complete source rather than claiming cross-resource rollback.
- The response-loss repair uses two existing durable boundaries in order: authenticated maintenance evidence records the deterministic intended operation before BlobStore, and Plan 07-14's single canonical destination authority records and replays the exact `MutationSpec`. Neither record adopts a destination entry from key presence, listing, path, or timing.
- D-11 is enforced by using only Plan 07-14's internal projection-suppressed maintenance wrapper during canonical rebuild staging. Verification and `accept_rebuild` do not run projections; after acceptance, the existing `rebuild_projection(plan, controller)` is the sole explicit derived operation and remains unable to authorize or revoke canonical publication.
- The validated obstore spike fixes the handler boundary regardless of payload participant: source and destination handlers keep `CacheHandler.put(data, Path, config)` / `CacheHandler.get(Path, metadata)`, store-local custom registration, private guarded staging, native suffix checks, descriptor identity, containment, and synchronous snapshot lifetime. This plan does not install or expose obstore.
</planner_assumptions>
