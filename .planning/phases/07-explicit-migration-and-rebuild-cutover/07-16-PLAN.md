<interfaces>
`MigrationCompatibilityEdge(source, destination, name, test_only)` currently tests only `source`. `HandlerRegistry.resolve_payload_transformation(handler_type, source_format, source_version, target_format, target_version)` returns exactly one registered handler plus `PayloadTransformationEdge`. `CacheHandler.transform_payload(snapshot, edge, destination_io, key, config)` owns the changed native payload contract. `BlobManifest` carries handler type, payload format/version, catalog values, locator, digest, and size and must be signed canonically.
</interfaces>

<planner_assumptions>
- MIGR-04 treats an advertised edge as executable only when the inspected source and configured destination identities both equal the edge endpoints; changed handler contracts are not byte-copy compatible.
- MIGR-06 routes missing, ambiguous, or non-executable changed-contract edges to the existing explicit rebuild/refusal classification rather than inventing conversion.
- WR-02 is adjudicated narrowly in this plan: a handler may keep the default empty edge set, but once it declares a directed edge the resolved implementation must differ from `CacheHandler.transform_payload`; this prevents an advertised executable edge from reaching the inherited always-rejecting method without imposing a universal converter or broader handler protocol.
- The obstore spike validates that path-based built-in and MCAP-style custom handlers survive only when `GuardedHandlerIO` retains private staging, safe suffixes, path containment, descriptor identity, and synchronous snapshot lifetime. This plan preserves those contracts and introduces no obstore dependency, participant handle, or stream-based handler API.
</planner_assumptions>
