<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| metadata store to verifier | Metadata fields and `entry_signature` can be attacker-controlled when the metadata backend is writable by an attacker. |
| stored signature to signer | The stored version prefix controls signature payload/key selection unless minimum-version policy blocks downgrades. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-01 | Tampering | `CacheEntrySigner.verify_entry` | mitigate | Reject parsed signature versions below `SecurityConfig.minimum_signature_version` per D-01 through D-04. |
| T-31-02 | Elevation of Privilege | unsigned metadata entries | mitigate | Document D-06 and D-07 so users do not rely on signatures when `allow_unsigned_entries=True` under attacker-writable metadata. |
| T-31-SC | Tampering | package supply chain | accept | No package-manager installs are planned; use existing stdlib and project dependencies only. |
</threat_model>
