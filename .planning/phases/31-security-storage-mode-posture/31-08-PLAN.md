Close the SEC-03 verification gap found after the Phase 31 controlled final sweep.

</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| active key file to signer | The active key remains authoritative for ordinary reads and completed rotations. |
| staged key file to interrupted-rotation fallback | `<keyfile>.new` is trusted only as a sibling staged by rotation and only while the active key file is unchanged. |
| metadata to verification/decryption | Metadata can contain signatures and encryption IVs produced before key publication; readers must not delete valid interrupted-rotation entries. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-31-08-01 | Denial of Service | `UnifiedCache._verify_entry()` | mitigate | Try staged signer verification before invalid-signature deletion when `<keyfile>.new` exists, so hard-interrupted rotation does not delete entries. |
| T-31-08-02 | Denial of Service | `BlobStore._verify_entry_signature()` | mitigate | Apply the same staged signer fallback while preserving SEC-04 canonical-plus-legacy verification order. |
| T-31-08-03 | Information Disclosure / Tampering | `BlobStore._read_encrypted_blob()` | mitigate | Use staged encryption key only after active-key decrypt failure and only from a valid 32-byte `<keyfile>.new`; do not expose plaintext temp files beyond the existing SEC-02 hardened path. |
| T-31-08-04 | Elevation of Privilege | staged key acceptance | mitigate | Do not accept metadata-only staged signatures; fallback requires the protected staged key file sibling and never changes `allow_unsigned_entries` behavior. |
| T-31-08-SC | Tampering | package supply chain | accept | No package-manager installs are planned. |
</threat_model>
