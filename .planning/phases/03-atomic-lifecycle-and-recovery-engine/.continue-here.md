## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Blocking lock before bounded retry | Key initialization enters blocking `flock`/`LockFileEx` before its attempt loop, so the nominal retry bound does not bound elapsed time. | blocking | Add policy deadline plus nonblocking retry/backoff on POSIX and Windows; prove timeout, release-before-deadline, process-loss, and descriptor cleanup. |
| Filesystem-order scan with lexical cursor | `scandir()` order is unspecified, but the cursor rejects lexically earlier names; reverse creation order skipped entries and sidecar cursor namespace mismatch livelocked. | blocking | Implement a genuinely stable backend inventory/index or authenticated snapshot and assert no skip/duplicate under insertion, deletion, restart, and reverse order. |
| Double-charged apply work | Completed orphan sidecars are retired in a pre-pass and charged again from unchanged SAFE findings; exact repository conflicts also escape the per-finding boundary. | blocking | Normalize apply into one action stream, charge once per attempted action, and isolate exact-byte conflicts while continuing later work. |
| Trusting existing test oracles | Tests counted successful deletion effects instead of calls and used lexical creation order, allowing replay and cursor bugs to pass. | advisory | Assert call counts, namespace inspection counts, artifact states, tokens, and later-action progress—not only final state. |
