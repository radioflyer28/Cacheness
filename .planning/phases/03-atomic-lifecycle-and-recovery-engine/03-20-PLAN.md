## Supported Topology and Guarantee Classification

| Scope item | Classification | Required Phase 3 outcome |
|---|---|---|
| STOR-03 | Integrity/safety | SQLite promotion is the only visibility point; readers see the old or new authenticated complete generation. |
| STOR-04 | Recovery plus integrity | Durable intent precedes managed payload publication; exact pre-promotion residue and post-promotion cleanup debt survive interruption. |
| STOR-05 | Integrity plus recovery | Overwrite, delete, clear, and close repeat idempotently and never reclaim a currently committed locator. |
| STOR-06 | Recovery | Dry-run is non-mutating; apply pages indexed authority work, revalidates exact evidence, checkpoints progress, and resumes. |
| STOR-07 | Integrity plus progress | Exact lineage CAS prevents disagreement; under contention each call succeeds, conflicts, or returns a documented typed retryable timeout. Distinct-key payload work remains outside authority transactions. |
| Authority transaction latency, contention distributions, clear/page throughput | Performance | Dedicated benchmark evidence detects regression and does not alter runtime correctness or require every sample to succeed. |

The supported durable topology is one host with multiple processes, a stdlib SQLite `LifecycleAuthority`, and local filesystem blobs. The authority transaction covers only SQLite-owned lifecycle rows. Native payload staging, immutable publication/fsync, verification, quarantine/deletion, and projection export occur outside that transaction and converge through durable intent, exact identity checks, cleanup debt, and reconciliation. Memory authority is same-process-only. PostgreSQL/multihost authority, shared remote blobs, and broad topology composition are deferred to Phase 4/5; existing compatibility behavior remains protected but is not promoted into a Phase 3 topology claim.
