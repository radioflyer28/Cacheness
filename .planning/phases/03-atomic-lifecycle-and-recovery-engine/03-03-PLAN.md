<objective>
Harden operation evidence and operational limits before generalized destructive recovery consumes them.

Purpose: Make recovery decisions safe against hostile control metadata and bounded under large stores.
Output: Exact authenticated evidence codec, stable paged repository, config-owned LifecycleLimits, and adversarial Wave 0 tests.
</objective>

## Artifacts this phase produces

- Completed internal `LifecycleOperationRecord` codec, transition validator, and domain-separated authentication projection.
- New internal `OperationPage`, `OperationCursor`, and repository methods `list_page`, `create_exclusive`, `checkpoint_if_exact`, and `retire_if_exact`.
- New frozen public configuration value `LifecycleLimits` owned by `src/cacheness/config.py`, composed into `CacheConfig` as `lifecycle_limits`, with explicit page/action/record/grace/close-wait fields and validation.
- Updated `src/cacheness/__init__.py` re-exports `LifecycleLimits` through the established top-level configuration surface; storage modules import the value from `cacheness.config` and do not declare a second policy type.
- Updated `BlobStore` accepts a backward-compatible keyword-only `config: CacheConfig | None` path, preserves the supplied `CacheConfig` object, and hands the exact `config.lifecycle_limits` instance to lifecycle/repository factories; Plans 03-05, 03-07, and 03-09 extend that same handoff to manifest paging, reconciliation, and instance admission/close.
- New test file `tests/test_blob_store_reconciliation.py`.
