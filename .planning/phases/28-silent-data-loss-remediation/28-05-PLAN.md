<task type="auto">
  <name>Task 3: Restrict hash and string fallback behavior</name>
  <files>src/cacheness/serialization.py, tests/test_serialization.py, tests/test_cache_key_consistency.py</files>
  <read_first>
    - src/cacheness/serialization.py fallback 5 and fallback 6
    - src/cacheness/config.py SerializationConfig

  <action>
Implement TASK-4 fallback rules:

1. Only use `hash()` for stable scalar types listed by TASK-4: `int`, `float`,
   `bool`, `complex`, `decimal.Decimal`, `datetime.date`,
   `datetime.datetime`, `datetime.time`, Enum members by name, and `None`.
2. For other hashable objects, log a warning once and fall through.
3. In string fallback, detect default memory-address repr strings containing
   `" object at 0x"`.
4. Replace the address-bearing string with a stable low-quality marker such as
   `{type(obj).__name__}:unstable_repr`.
5. Log a warning that the key material is low quality.
6. Avoid raw default repr in persistent key material.
  </action>
  <verify>
    <automated>uv run pytest tests/test_serialization.py tests/test_cache_key_consistency.py tests/test_decorators.py tests/test_core.py -x -q --ignore=tests/test_tensorflow_handler.py</automated>
  </verify>
  <acceptance_criteria>
    - Python `hash()` is not used for arbitrary object, tuple, set, frozenset, or string-containing fallback paths.
    - Enum fallback uses stable names/values rather than process-randomized hash.
    - Default repr memory addresses do not enter cache-key strings.
    - Warnings are emitted for skipped unstable hash fallback and low-quality repr fallback.
  </acceptance_criteria>
</task>
